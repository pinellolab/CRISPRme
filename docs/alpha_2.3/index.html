1 — What’s new in 2.3 (dict-less)

A dict-less variant-aware index replaces the classic ~152 GB per-sample SNP dictionaries (Dictionaries/dictionaries_<vcf>/) with two additive, much smaller tiers:

  • Tier 0 — registry (Dictionaries/registry_<vcf>/): a compact registry that gives out-of-the-box off-target detection with corrected allele frequencies and rsIDs, no source VCFs required.
  • Tier 1 — genotype store (Dictionaries/genotypes_<vcf>/): the larger per-sample store that reconstructs the Samples column at post-analysis time. It rides along as a separate companion tarball and is fetched automatically on download (skip it with --no-genotypes for detection-only).

The dict-less index also adds a population_summary companion (per-database / super-population / global frequencies) and keeps the indel logs (Dictionaries/log_indels_<vcf>/) that indel post-analysis still needs — the tiers are SNP-only. Together the registry + genotype tiers stand in for the old per-sample dictionaries, so a downloaded variant index is self-complete and dramatically smaller on disk. Everything is backward-compatible: existing dict-based searches are unchanged.

2 — Try it in the browser (recommended)

The recommended path: run the CRISPRme+ web interface in a container — Docker on a laptop or desktop, or Apptainer / Singularity on an HPC cluster. Both launch the same app at http://127.0.0.1:8080. Work in an empty directory; everything is written there and persists.

2.1 — Setup — Docker

Pull the pinned CRISPRme+ 2.3 image, then fetch --what all first (genome, PAMs, annotations, samplesID scaffolding), then both published indexes: the reference index (NRG_3_hg38) and the dict-less variant index. The variant download strips the -dictless marker and installs under its canonical name (genome_library/NRG_3_hg38+hg38_1000G_HGDP/), pulls the Tier-1 genotype companion automatically, and installs the bundled samplesID lists — so no separate --what samples is needed. 

docker pull pinellolab/crisprme:v2.3.3
mkdir -p ~/crisprme-2.3 && cd ~/crisprme-2.3
docker run --rm -v "${PWD}:/DATA" -w /DATA pinellolab/crisprme:v2.3.3 crisprme.py download --what all --path /DATA
docker run --rm -v "${PWD}:/DATA" -w /DATA pinellolab/crisprme:v2.3.3 crisprme.py download --what index --index-name NRG_3_hg38 --path /DATA
docker run --rm -v "${PWD}:/DATA" -w /DATA pinellolab/crisprme:v2.3.3 crisprme.py download --what index --index-name NRG_3_hg38-dictless+hg38_1000G_HGDP --path /DATA

Downloading the reference index (NRG_3_hg38, ~8.9 GB) is recommended: the default 2-bulge search needs it, and having it on disk lets CRISPRme reuse it instead of building it on demand (a one-time, ~40-minute step the first time you run a bulge search). Both indexes install side by side under genome_library/.

Then launch the web interface:

docker run --rm -v "${PWD}:/DATA" -w /DATA -p 8080:8080 -it pinellolab/crisprme:v2.3.3 crisprme.py web-interface

Leave it running and open http://127.0.0.1:8080. Stop with Ctrl+C. Everything lands in ~/crisprme-2.3 on your computer (the -v "${PWD}:/DATA" bind-mount) and persists, even though each container is --rm. Downloads resume if interrupted — if one stops, just re-run the same command. To skip the big genotype companion (detection-only), add --no-genotypes to the index download; per-sample Samples are then degraded until the store is present.

2.2 — Setup — Apptainer / Singularity (alternative, e.g. HPC)

On HPC clusters Docker often isn’t available; most clusters already have Apptainer / Singularity, which needs no root and no daemon. On older systems the command is singularity instead of apptainer; they are interchangeable. Convert the pinned image to a local .sif file (one time), then download the same data and dict-less index: 

apptainer pull crisprme.sif docker://pinellolab/crisprme:v2.3.3
mkdir -p ~/crisprme-2.3 && cd ~/crisprme-2.3
apptainer run --bind "${PWD}:/DATA" --pwd /DATA crisprme.sif crisprme.py download --what all --path /DATA
apptainer run --bind "${PWD}:/DATA" --pwd /DATA crisprme.sif crisprme.py download --what index --index-name NRG_3_hg38 --path /DATA
apptainer run --bind "${PWD}:/DATA" --pwd /DATA crisprme.sif crisprme.py download --what index --index-name NRG_3_hg38-dictless+hg38_1000G_HGDP --path /DATA

Then launch the web interface:

apptainer run --bind "${PWD}:/DATA" --pwd /DATA crisprme.sif crisprme.py web-interface

Open http://127.0.0.1:8080 (or, on a cluster, the node’s address). Apptainer shares the host network, so no port mapping is needed — the port maps straight to localhost — but port 8080 must be free on the node. Use apptainer run (not exec): run activates the environment inside the image so crisprme.py is on the path.

2.3 — In the browser

Once the web app is open, in the web form:

  • Pick genome hg38 and the SpCas9 (NRG) variant index — the dict-less 1000G + HGDP index you just downloaded.
  • Paste the CPS1 guide: CTAACAGTTGCTTTTATCAC. The UI auto-pads the guide, so no NNN PAM placeholder is needed.
  • Leave the defaults as-is — 6 mismatches, 2 DNA bulges, 2 RNA bulges, capped at 4 total edits — then click Submit. (Open Advanced options to adjust the per-type caps; the bulge dropdowns offer up to 2 of each, matching the downloaded index.)

When the job finishes you land on the results page. You should get the CPS1 off-target from the CRISPRme paper — at chr2:210,530,658, CFD 0.947, rs114518452, gene CPS1 — with a non-empty Samples column from the genotype tier and a population summary (per-database / super-population / global allele frequencies). Both come from the dict-less tiers: the same compact install (the Tier-0 registry_ + Tier-1 genotypes_ stores, with no ~152 GB per-sample SNP dictionaries) powers the whole thing — the dict-less index is fully usable from the web. Results are saved on your own machine under ~/crisprme-2.3/Results/ (see “Where are my results?” below).

3 — Command-line quick example

Prefer the CLI? Here is the same search headless, with Docker. Work in an empty directory; everything is written there and persists between the --rm containers.

3.1 — Pull the image

docker pull pinellolab/crisprme:v2.3.3

You can also use the unpinned pinellolab/crisprme:latest, but prefer the pinned tag for a reproducible test.

3.2 — Download the reference data, then the dict-less index

Fetch --what all first (genome, PAMs, annotations, samplesID scaffolding), then both the reference index (NRG_3_hg38) and the dict-less variant index. The variant download strips the -dictless marker and installs under its canonical name (genome_library/NRG_3_hg38+hg38_1000G_HGDP/), pulls the Tier-1 genotype companion automatically, and installs the bundled samplesID lists — so no separate --what samples is needed. 

mkdir -p ~/crisprme-2.3 && cd ~/crisprme-2.3
docker run --rm -v "$PWD":/DATA -w /DATA pinellolab/crisprme:v2.3.3 crisprme.py download --what all
docker run --rm -v "$PWD":/DATA -w /DATA pinellolab/crisprme:v2.3.3 crisprme.py download --what index --index-name NRG_3_hg38
docker run --rm -v "$PWD":/DATA -w /DATA pinellolab/crisprme:v2.3.3 crisprme.py download --what index --index-name NRG_3_hg38-dictless+hg38_1000G_HGDP

Downloading the reference index (NRG_3_hg38, ~8.9 GB) lets the 2-bulge search below reuse it (“Reference index present (NRG_3_hg38)” in the log) instead of a one-time, ~40-minute on-demand build.

Downloads resume if interrupted — if one stops, just re-run the same command. To skip the big genotype companion (detection-only), add --no-genotypes to the index download; per-sample Samples are then degraded until the store is present.

3.3 — Create the three tiny config files

The search takes the guide, the VCF listing, and the samplesID listing as small text files. Create them in the same directory: 

printf 'CTAACAGTTGCTTTTATCACNNN\n' > cps1_guide.txt
printf 'hg38_1000G_HGDP\n'          > vcf_list.txt
printf 'hg38_1000G_HGDP.samplesID.txt\n' > samples_list.txt

The guide (CTAACAGTTGCTTTTATCACNNN) is the CPS1 spacer with the NNN PAM placeholder; vcf_list.txt names the combined 1000G + HGDP dataset; samples_list.txt points at the combined samplesID file that ships inside the index.

3.4 — Run the search

Use the NRG SpCas9 PAM (NAG + NGG) so the variant-created NAG CPS1 off-target is in scope, with the defaults — 6 mismatches, 2 DNA and 2 RNA bulges, capped at 4 total edits: 

docker run --rm -v "$PWD":/DATA -w /DATA pinellolab/crisprme:v2.3.3 crisprme.py complete-search \
  --genome Genomes/hg38 \
  --vcf vcf_list.txt \
  --samplesID samples_list.txt \
  --guide cps1_guide.txt \
  --pam PAMs/20bp-NRG-SpCas9.txt \
  --annotation Annotations/dhs+encode+gencode.hg38.bed.gz \
  --gene_annotation Annotations/gencode.protein_coding.bed.gz \
  --mm 6 --bDNA 2 --bRNA 2 --max-total-edits 4 \
  --output cps1_test

Because both indexes are already on disk — the reference index (NRG_3_hg38) and the prebuilt dict-less variant index (with its tiers and samplesID lists) — the search reuses them and skips the reference-index build and variant enrichment entirely. The log shows “Reference index present” and “Variant index present” rather than an indexing step.

4 — What to expect (how to know it worked)

This applies to either path above — the browser search (section 2) or the headless CLI search (section 3).

On disk — the tiers, not the giant dictionaries. Check the install:

ls Dictionaries/

You should see the dict-less tiers and no ~152 GB dictionaries folder:

  • registry_hg38_1000G_HGDP/ — the Tier-0 registry (detection + corrected AF/rsID)
  • genotypes_hg38_1000G_HGDP/ — the Tier-1 genotype store (per-sample Samples)
  • log_indels_hg38_1000G_HGDP/ — the indel logs (kept; indel post-analysis needs them)
  • NO dictionaries_hg38_1000G_HGDP/ — the big ~152 GB per-sample SNP dicts are gone

In the results — the CPS1 off-target. The integrated results table should contain the CPS1 off-target from the CRISPRme paper:

ls Results/cps1_test/*integrated_results.tsv
  • Off-target at chr2:210,530,658
  • CFD 0.947
  • rsID rs114518452, gene CPS1
  • a non-empty Samples column, reconstructed from the Tier-1 genotype store (this is the proof the dict-less genotype tier works)

You should also find a *.population_summary.tsv companion under Results/cps1_test/ with per-database, per-super-population, and global allele frequencies.

If detection works (the chr2:210,530,658 row is present with the right CFD/rsID) but the Samples column is empty, you likely downloaded with --no-genotypes — the Tier-1 store was skipped. Re-run the index download without that flag.

5 — Where are my results?

Every search writes to Results/<job>/ on disk (under your working directory — e.g. ~/crisprme-2.3/Results/<job>/), and the web interface serves the same outputs under its result tabs. The headline files, and which tab shows each:

*integrated_results.tsv
(download: ..._integrated_results.zip)		 Main precomputed / integrated table — one row per off-target, with ref/alt CFD, variant, rsID, MAF, gene, and Samples. Custom Ranking
imgs/CRISPRme_CFD_top_1000_by_variant_effect_<guide>.png
(also .pdf; a CRISTA variant too)		 REF/ALT plot for the top 1000 targets ranked by largest |ALT−REF| CFD change. (CRISPRme_CFD_top_1000_log_for_main_text_<guide>.png = top-1000 by score.) Graphical Reports (“Top 1000 by variant effect”)

The personal risk cards (Personal Risk Cards tab) are generated on demand from the web interface — pick an individual to build a variant-aware report for that sample.

6 — Build your own dict-less index (optional)

To build a dict-less variant-aware index for your own cohort, build with --vcf and --samplesID (the --samplesID listing is required to emit the tiers; without it you silently get a dicts-only index with no Tier-0 registry, no Tier-1 genotype store, and — for a merged panel — no combined samplesID list), then publish with --dictless: 

# Build the variant-aware index (tiers emitted because --samplesID is passed)
crisprme.py build-index-only \
  --genome Genomes/hg38 --pam PAMs/20bp-NRG-SpCas9.txt \
  --bDNA 2 --bRNA 2 --thread 16 \
  --vcf VCFs/hg38_1000G_HGDP --samplesID samplesIDs.config.txt \
  --path "$CRISPRME_DIR"
# -> genome_library/NRG_3_hg38+hg38_1000G_HGDP/  (+ _INDELS)
#    Dictionaries/registry_hg38_1000G_HGDP/      (Tier-0)
#    Dictionaries/genotypes_hg38_1000G_HGDP/     (Tier-1)
#    samplesIDs/hg38_1000G_HGDP.samplesID.txt    (combined, emitted by the build)

# Publish: --dictless drops the ~152 GB per-sample SNP dicts (tiers replace them),
# keeps the indel logs, and uploads a separate genotypes_<vcf>.tar.gz companion.
export HF_TOKEN=hf_...        # your write token, in the shell only
crisprme.py publish-index --index genome_library/NRG_3_hg38+hg38_1000G_HGDP --dictless

--samplesID is a listing file (one samplesID filename per line, resolved under samplesIDs/); a combined 1000G + HGDP panel lists both hg38_1000G.samplesID.txt and hg38_HGDP.samplesID.txt. See the full build/publish/download reference for details:

7 — Notes

  • Dict-based stays the default. The dict-based NRG_3 / NGG_3 indexes remain the default; the dict-less index is opt-in (fetched by its explicit -dictless name) until a later flip.
  • Order matters. Run download --what all before download --what index — the index download relies on the reference data and samplesID scaffolding being in place.
  • Genotype companion is optional. Off-target detection works from the Tier-0 registry alone; the Tier-1 genotype store (fetched by default, skippable with --no-genotypes) is what reconstructs the per-sample Samples column.
  • Alpha status. This line is under active testing. Please open an issue with anything that looks off.
